# Story 9.5: Import Domain Configuration

## Status
Ready for Development

## Story
**As a** pharmacy informaticist,
**I want** to import a domain configuration file and parse its ingredients,
**so that** I can analyze and manage configurations from different health systems

## Acceptance Criteria
1. Support JSON format
2. Parse and extract ingredient data with field mapping
3. Parse and extract test case data from configurations
4. Detect configuration format automatically
5. Display import progress with cancel option
6. Show preview of parsed data before confirmation
7. Handle errors gracefully with specific error messages
8. Store imported configuration with domain metadata
9. Generate import summary report

## Dev Notes

### Previous Story Context
Story Group 1 (9.1-9.4) established the variant management system. This story begins the configuration import/export group, enabling bulk data ingestion from external health systems.

### Data Models
**Configuration Import Types** [New]
```typescript
interface DomainConfiguration {
  id: string;
  domain: string;
  healthSystem: string;
  fileName: string;
  fileFormat: 'json' | 'csv' | 'excel' | 'xml';
  importedAt: Date;
  importedBy: string;
  ingredients: ConfigIngredient[];
  metadata: ImportMetadata;
  mappingTemplate?: FieldMapping;
}

interface ConfigIngredient {
  externalId: string;
  name: string;
  concentration?: string;
  unit?: string;
  category?: string;
  customFields: Record<string, any>;
  tests?: TestCase[];
}

interface TestCase {
  id: string;
  name: string;
  variables: Record<string, any>;
  expected?: string;
  description?: string;
  enabled?: boolean;
  tags?: string[];
}

interface ImportMetadata {
  totalRecords: number;
  successfulRecords: number;
  failedRecords: number;
  warnings: string[];
  processingTime: number;
  fileSize: number;
}

interface FieldMapping {
  id: string;
  name: string;
  sourceField: string;
  targetField: string;
  transformation?: string;
}
```

### File Format Schemas
**Expected JSON Structure**:
```json
{
  "domain": "health-system-name",
  "ingredients": [
    {
      "id": "123",
      "name": "Amino Acid 10%",
      "concentration": "10",
      "unit": "%",
      "tests": [
        {
          "id": "test-1",
          "name": "Standard dosing test",
          "variables": {"weight": 70, "age": 30},
          "expected": "2.1 g/kg/day"
        }
      ]
    }
  ]
}
```

**CSV Format**:
```csv
ID,Name,Concentration,Unit,Category
123,"Amino Acid 10%",10,%,Macronutrient
```

### Third-Party Libraries
**Parsing Libraries** [Source: architecture/tech-stack.md - extend as needed]
- Papa Parse: CSV parsing (lightweight, battle-tested)
- xlsx: Excel file parsing
- fast-xml-parser: XML parsing
- File API: Browser file handling

### File Size Limits
- Maximum file size: 10MB
- Chunk large files for processing
- Use Web Workers for parsing to avoid blocking UI

### Firebase Structure
**Collections**:
```
domain_configurations/
  {configId}/
    - domain: string
    - healthSystem: string
    - ingredients: array
    - metadata: object
    - mappingTemplate: object
```

### Performance Optimization
- Parse files in Web Worker to avoid blocking UI
- Stream large CSV files if possible
- Batch Firebase writes (500 records per batch)
- Show progress for files >1MB
- Cancel support for long operations

### File Locations
**Based on FSD Architecture** [Source: architecture/source-tree.md]

### Security Considerations
- Validate file size before processing
- Sanitize all imported data with DOMPurify
- Check for malicious patterns in files
- Limit memory usage during parsing
- Validate against schema before saving
- No execution of imported code

### UI/UX Flow
1. User clicks "Import Configuration"
2. Select or drag file
3. Auto-detect format
4. Map fields if needed
5. Preview parsed data
6. Confirm import
7. Show progress
8. Display summary report
