# Story 9.1: View Ingredient Variants

## Status
Ready for Review

## Story
**As a** pharmacy informaticist,
**I want** to view ingredients grouped by type with their variants organized by population and health system,
**so that** I can understand and manage the different configurations across domains and identify sync issues

## Acceptance Criteria
1. Display ingredients grouped by ingredient type as primary grouping
2. Show distinct list of ingredients initially (no variants visible)
3. Expand ingredient to show variants organized by population and health system
4. Indicate which variants have complete section data (static and dynamic)
5. Show test case count and status for each ingredient and variant
6. Provide visual indicators for validation status of each variant
7. Show sync status indicators when config files are out of sync across domains
8. Enable expansion/collapse of ingredient groups for easier navigation
9. Display metadata for each variant (last updated, version, validation status, sync status, test status)

### Data Models
**IngredientVariant Interface** [Source: EPIC-9-CONFIG-MANAGEMENT.md]
```typescript
interface IngredientVariant {
  id: string;
  ingredientId: string;
  ingredientType: 'Macronutrient' | 'Micronutrient' | 'Additive' | 'Salt' | 'Diluent' | 'Other';
  population: 'NEO' | 'CHILD' | 'ADOLESCENT' | 'ADULT';
  healthSystem: string;
  domain: string;
  subdomain: string;
  sections: {
    static: Section[];
    dynamic: DynamicSection[];
  };
  tests: TestCase[];
  lastUpdated: Date;
  validationStatus: ValidationStatus;
  syncStatus: 'synced' | 'conflict' | 'outdated' | 'unknown';
  version: string;
  domainVersions?: {
    [domain: string]: {
      version: string;
      lastUpdated: Date;
    };
  };
}

interface Ingredient {
  id: string;
  name: string;
  keyname: string;
  display: string;
  type: 'Macronutrient' | 'Micronutrient' | 'Additive' | 'Salt' | 'Diluent' | 'Other';
  variants: IngredientVariant[];
  tests: TestCase[];
  hasSyncConflicts: boolean;
}

interface TestCase {
  id: string;
  name: string;
  variables: Record<string, any>;
  expected?: string;
  description?: string;
  enabled?: boolean;
  tags?: string[];
}
```

### Sync Status Detection
**Sync Comparison Logic**:
- Compare version numbers across domains for each ingredient variant
- Detect when config files have different lastUpdated timestamps
- Identify conflicts when multiple domains have different content
- Flag outdated variants when newer versions exist in other domains

### UI/UX Patterns
**Status Indicators**:
- ✅ Green CheckCircle: All content is valid HTML/text
- ⚠️ Yellow Warning: Minor content issues (malformed HTML, suspicious content)
- ❌ Red Error: Invalid content (broken HTML, empty required content)
- ⏳ Gray Clock: Content validation pending or outdated

**Test Status Indicators**:
- 🧪 TestPassed: All tests passing
- ❌ TestFailed: Some tests failing
- ⏳ TestPending: Tests not yet run
- 📊 TestCount: Show test count badge (e.g., "5 tests")

**Sync Status Indicators**:
- 🔄 Sync: All domains in sync
- ⚠️ SyncProblem: Sync conflicts detected
- ⏳ Outdated: Some domains have newer versions
