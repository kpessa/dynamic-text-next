# Story 9.3: Manage Variant Sections

## Status
Ready for Development

## Story
**As a** pharmacy informaticist,
**I want** to manage static and dynamic sections for each ingredient variant,
**so that** I can define both fixed content and calculated values specific to each population and health system

## Acceptance Criteria
1. Display list of sections for selected variant with type indicators (static/dynamic)
2. Allow adding new sections with name, type, and content
3. Enable editing existing section content with appropriate editor (text/code)
4. Support reordering sections via drag-and-drop
5. Provide section deletion with confirmation dialog
6. Validate dynamic section JavaScript syntax before saving
7. Show preview of dynamic section output with test variables
8. Auto-save section changes with optimistic updates
9. Display test case counts and status for each section
10. Enable test case management within section context

### Data Models
**Section Interface** [Source: architecture/data-models.md]
```typescript
interface Section {
  id: string;
  type: 'html' | 'javascript';
  content: string;
  order: number;
  title?: string;
  description?: string;
  enabled?: boolean;
  tests: TestCase[];  // Test cases for this section
}

interface DynamicSection extends Section {
  type: 'javascript';
  variables?: string[];  // Extracted variable names
  lastValidated?: Date;
  validationErrors?: ValidationError[];
}

interface TestCase {
  id: string;
  name: string;
  variables: Record<string, any>;
  expected?: string;
  description?: string;
  enabled?: boolean;
  tags?: string[];
}
```

**Secure Code Execution** [Source: architecture/components.md]
```typescript
class SecureExecutor {
  async execute(code: string, context: TPNContext): Promise<Result>
  transpile(code: string): string  // Babel transpilation
  sanitizeContext(context: any): SafeContext
  validateCode(code: string): ValidationResult
}
```

### Component Architecture
**Web Worker Setup** [Source: architecture/frontend-architecture.md]
- Worker file location: `public/workers/code-executor.worker.js`
- Timeout: 5000ms maximum execution time
- Sandbox: No access to DOM, network, or file system
- Context: Only TPN variables and helper functions

### Firebase Structure
**Sections Sub-collection**:
```
ingredient_variants/{variantId}/sections/{sectionId}
```
- Real-time listeners for collaborative editing
- Optimistic updates with rollback on failure

### Technical Constraints
- Maximum 500 lines per component [Source: architecture/coding-standards.md]
- All user input sanitized with DOMPurify [Source: architecture/coding-standards.md]
- Code execution always in sandboxed Web Workers [Source: architecture/coding-standards.md]
- Components >100 lines use React.memo [Source: architecture/coding-standards.md]

### Security Considerations
**Dynamic Code Execution**:
1. Never use eval() or Function() constructor
2. Always transpile with Babel before execution
3. Execute only in Web Worker sandbox
4. Limit execution time to 5 seconds
5. Sanitize all context variables
6. No network or DOM access in sandbox

### Performance Optimizations
- Virtual scrolling for long section lists
- Debounced auto-save (2 seconds)
- Memoized section components
- Lazy load code editor
- Cancel pending saves on unmount
