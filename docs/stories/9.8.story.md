# Story 9.8: Validate Imported Configurations

## Status
Draft

## Story
**As a** pharmacy informaticist,
**I want** to validate imported configurations against current section data,
**so that** I can ensure imported configurations are complete and compatible before deployment

## Acceptance Criteria
1. Compare imported ingredients against current variant sections
2. Identify missing or outdated sections in imported config
3. Check for schema compliance and data type validation
4. Validate business rules and constraints
5. Generate detailed validation report with issues
6. Provide fix suggestions for validation failures
7. Support batch validation of multiple configurations
8. Allow validation rule customization per domain

### Data Models
**Validation Types** [New]
```typescript
interface ValidationContext {
  configuration: DomainConfiguration;
  currentSections: Section[];
  validationRules: ValidationRule[];
  domainRequirements: DomainRequirements;
}

interface ValidationResult {
  configurationId: string;
  timestamp: Date;
  status: 'passed' | 'failed' | 'partial';
  issues: ValidationIssue[];
  coverage: CoverageMetrics;
  suggestions: FixSuggestion[];
}

interface ValidationIssue {
  id: string;
  severity: 'error' | 'warning' | 'info';
  type: 'missing' | 'outdated' | 'invalid' | 'incompatible';
  ingredientId?: string;
  sectionName?: string;
  field?: string;
  message: string;
  details: Record<string, any>;
}

interface FixSuggestion {
  issueId: string;
  type: 'auto' | 'manual' | 'template';
  description: string;
  action?: () => void; // For auto-fixes
  example?: string;
  documentation?: string;
}

interface CoverageMetrics {
  totalIngredients: number;
  validIngredients: number;
  totalSections: number;
  completeSections: number;
  coveragePercent: number;
}

interface DomainRequirements {
  domain: string;
  requiredSections: string[];
  optionalSections: string[];
  businessRules: BusinessRule[];
  schemaVersion: string;
}
```

### Validation Rule Categories

**Schema Validation Rules**:
```typescript
const schemaRules = {
  ingredient: {
    name: { required: true, type: 'string', maxLength: 100 },
    concentration: { required: false, type: 'number', min: 0, max: 100 },
    unit: { required: false, type: 'string', enum: ['%', 'mg', 'mL'] }
  }
};
```

**Business Rules Examples**:
```typescript
const businessRules = [
  {
    name: 'ConcentrationRange',
    check: (ing) => ing.concentration >= 0 && ing.concentration <= 100,
    message: 'Concentration must be between 0 and 100'
  },
  {
    name: 'RequiredForNeonatal',
    check: (ing, pop) => pop !== 'neo' || ing.hasSection('dosing'),
    message: 'Neonatal ingredients require dosing section'
  }
];
```

### Validation Severity Levels
- **Error**: Blocks deployment, must be fixed
- **Warning**: Should be reviewed but doesn't block
- **Info**: Suggestions for improvement

### Fix Suggestion Templates
```typescript
const fixTemplates = {
  missingSections: {
    description: 'Add missing {sectionName} section',
    template: 'Default content for {sectionName}',
    autoFix: true
  },
  outdatedFormat: {
    description: 'Update to new format version',
    migration: 'Run migration script',
    autoFix: false
  }
};
```

### Performance Considerations
- Use Web Workers for validation of large configs
- Cache validation schemas and rules
- Batch validate in chunks of 50 ingredients
- Progressive validation with early exit on critical errors
- Debounce re-validation triggers
